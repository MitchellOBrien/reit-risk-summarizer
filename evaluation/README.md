# Evaluation System

This directory contains the evaluation infrastructure for measuring LLM performance on REIT risk summarization.

## Directory Structure

```
evaluation/
├── golden_dataset.csv          # Expert-curated reference risks (ground truth)
├── golden_outputs/             # Cached LLM outputs (API response cache)
│   ├── AMT.json
│   ├── PLD.json
│   └── EQIX.json
├── results/                    # Evaluation reports with metrics
│   ├── evaluation_results.json # Detailed JSON metrics
│   └── evaluation_report.txt   # Human-readable summary
├── run_evaluation.py           # Main evaluation script
├── golden_output_manager.py    # LLM output caching utilities
├── metrics.py                  # Metric calculation functions
└── evaluator.py                # Legacy evaluator (deprecated)
```

## Key Files Explained

### `golden_dataset.csv`
- **Purpose**: Ground truth dataset with expert-curated risks
- **Content**: 50 rows (10 tickers × 5 risks each)
- **Columns**: ticker, company_name, sector, risk_rank, risk_description
- **Usage**: Source of truth for evaluation comparisons

### `golden_outputs/*.json`
- **Purpose**: Cache of raw LLM API responses
- **Why cache?**: Avoid burning API tokens on repeated evaluation runs
- **Content**: Only LLM-generated risks + metadata (model, prompt_version, timestamp)
- **Does NOT contain**: Expert risks, metrics, or comparisons
- **File format**: `{TICKER}.json` (e.g., `AMT.json`)
- **Example structure**:
  ```json
  {
    "ticker": "AMT",
    "company_name": "American Tower",
    "model": "llama-3.3-70b-versatile",
    "prompt_version": "v1.0",
    "generated_at": "2026-01-22T10:00:00Z",
    "risks": [
      "Risk 1...",
      "Risk 2...",
      ...
    ]
  }
  ```

### `results/evaluation_results.json`
- **Purpose**: Comprehensive evaluation report with performance metrics
- **Content**: 
  - LLM-generated risks (copied from golden_outputs)
  - Expert risks (from golden_dataset.csv)
  - Calculated metrics (semantic_similarity, NDCG@5, sector_specificity)
  - Aggregate statistics (mean/min/max across all tickers)
  - Run metadata (date, mode, ticker count)
- **Structure**:
  ```json
  {
    "metadata": {
      "run_date": "2026-01-23T03:03:55.919099",
      "total_tickers": 10,
      "cached_only_mode": true
    },
    "tickers": [
      {
        "ticker": "AMT",
        "risks": [...],           // LLM-generated
        "expert_risks": [...],    // From golden_dataset.csv
        "metrics": {
          "semantic_similarity": 0.751,
          "ndcg_at_5": 0.900,
          "sector_specificity": 0.621
        }
      }
    ],
    "summary_metrics": {
      "semantic_similarity": {"mean": 0.751, "min": 0.551, "max": 1.0}
    }
  }
  ```

### `results/evaluation_report.txt`
- **Purpose**: Human-readable summary of evaluation metrics
- **Generated by**: `scripts/generate_evaluation_report.py` (automated in CI/CD)
- **Content**: Formatted text report with summary statistics and per-ticker breakdown
- **Usage**: Quick overview for PR comments, email notifications, or manual review
- **Note**: Auto-generated from `evaluation_results.json`, not manually edited

## Key Distinction

**Think of it like grading an exam:**

- `golden_dataset.csv` = Answer key (expert risks)
- `golden_outputs/*.json` = Student answers (LLM responses) - cached to avoid retaking the test
- `results/evaluation_results.json` = Graded exam (answers + scores + analytics)
- `results/evaluation_report.txt` = Summary report card (human-readable highlights)

## Running Evaluations

### Basic Usage

```bash
# Use cached outputs only (no API calls)
python -m evaluation.run_evaluation --cached-only

# Process specific tickers
python -m evaluation.run_evaluation --tickers AMT PLD EQIX

# Regenerate all outputs (ignore cache)
python -m evaluation.run_evaluation --regenerate

# Normal mode (use cache when available)
python -m evaluation.run_evaluation
```

### Command-Line Options

- `--cached-only`: Only use cached outputs (fail if cache missing)
- `--regenerate`: Ignore cached outputs and regenerate all from LLM
- `--tickers`: Process specific tickers (space-separated)
- `--dataset`: Path to golden dataset CSV (default: `golden_dataset.csv`)
- `--output`: Path for results JSON (default: `results/evaluation_results.json`)

## Metrics

### 1. Semantic Similarity (0-1)
- Measures how semantically similar LLM risks are to expert risks
- Uses sentence embeddings + cosine similarity
- **Target**: ≥ 0.75

### 2. NDCG@5 (0-1)
- Normalized Discounted Cumulative Gain at rank 5
- Measures ranking quality (are the most important risks ranked highest?)
- **Target**: ≥ 0.70

### 3. Sector-Specificity (0-1)
- Measures how specific risks are to the ticker's sector
- Compares similarity to own-sector vs. other-sector risks
- **Target**: ≥ 0.40 (Note: REIT sectors have legitimate overlap)

## Mock Data for Testing

Three quality levels are available in `golden_outputs/`:

1. **AMT.json** - Perfect match (similarity ≈ 1.0)
2. **PLD.json** - Good quality (similarity ≈ 0.70)
3. **EQIX.json** - Mediocre quality (similarity ≈ 0.55)

These enable testing the full evaluation pipeline without burning API tokens.

## Workflow

1. **Initial Setup**: Curate expert risks in `golden_dataset.csv`
2. **Generate LLM Outputs**: Run `run_evaluation.py` to call LLM and cache outputs
3. **Cached Evaluations**: Re-run with `--cached-only` to recalculate metrics without API calls
4. **Analysis**: Review `results/evaluation_results.json` for performance insights
5. **Iteration**: Adjust prompts/models and regenerate with `--regenerate`
